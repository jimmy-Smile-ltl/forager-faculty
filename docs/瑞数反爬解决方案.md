# 瑞数反爬解决方案 — 设计文档与排查手册

> **English summary**: This document details how this repository defeats
> **RiverSecurity (瑞数) dynamic WAF** — the most common anti-crawler protection
> on Chinese university websites and the main reason the `util/` request stack
> exists. Key ideas: (1) a 3-layer adversarial model (application-layer 412/202
> JS challenges are solvable in-process; network-layer TCP resets require a
> network change; IP blacklists are not programmatically bypassable); (2) a
> 5-level degradation chain `curl_cffi → system curl → iv8 → nodenv → sdenv →
> real browser`, where iv8/nodenv/sdenv are three pure-CPU solvers that execute
> the challenge VM without launching a browser; (3) per-domain cookie caching
> with authoritative invalidation (412), stale-cookie pollution detection, and
> path-mismatch (404) clearing; (4) concurrency safety via semaphores and flock
> launch locks for the resident browser. Sections below: threat model, solver
> comparison, cookie lifecycle, engineering rules, config switches, dependency
> installation, and a symptom→fix troubleshooting manual.

> 本文档解释本仓库如何对抗**瑞数（RiverSecurity）动态防护 WAF**——国内高校官网
> 最常见的反爬方案，也是本框架 `util/` 请求栈存在的最大理由。所有机制均以
> `util/` 下代码为准，实测数据来自代码注释中沉淀的实测记录。

## 实战规模

本方案在 **144 校全量运行**中经受 **5,000+ 院系站点**实战检验——覆盖全国高校
官网的主流 CMS 与 WAF 形态，配套**快代理隧道接入**（`util/proxy.py` /
`util/local_proxy.py`，凭证全部走环境变量，代码零硬编码）。三条纯 CPU 求解器
与浏览器层的组合使瑞数站点不再成为采集瓶颈。这不是纸面设计：412 语义误判、
cookie 污染、并发互搏、域名变体（www/裸域）、改版路径失效——每一条铁律背后
都是一类实测翻车现场，事故教训见下文「工程铁律」与「排查手册」。

## 瑞数是什么

瑞数在页面与浏览器之间插入一道 **JS 挑战（challenge）**：首次请求返回的不是
页面，而是一段混淆 VM 脚本；浏览器执行后生成动态 Cookie（O/P/S 系列），
携带该 Cookie 重访才能拿到真页。爬虫直接请求 → 拿到挑战页（或直接被断连）。

按拦截层位分三类（`handleRuishu.py` 模块文档的三层模型）：

| 层级 | 特征 | 代表 | 能否程序化突破 |
|---|---|---|---|
| **应用层瑞数** | HTTP 412/202，或 200 但 <500 字符且含 `document.cookie`/`$_ts.nsd` | 四川大学(202)、成都理工(412)、安徽大学(412) | ✅ 模拟浏览器执行 VM 生成 Cookie |
| **网络层瑞数** | TCP broken pipe / connection reset（TLS 握手前断连） | 兰州大学、西安交通大学 | ⚠️ 换网络出口才有效（换工具无效） |
| **IP 黑名单** | connection refused，任何工具连不上 | 个别站点阶段性封禁 | ❌ 换网络 / 等待解封 |

**判定函数**（`smart_fetch.py`，全链共享口径）：

- `_is_ruishu(text, status)`：412/202，或 200 短页含 `$_ts.nsd` / `document.cookie=`
- `_is_challenge_page(html)`：无特征码 WAF 挑战页（challengeId / "访问被限制" /
  `content_container` 壳 / `setTimeout("xx(N)")` eval 跳转壳等 8 种模式）；
  误伤保护——含 ≥3 个 `<a href>` 视为真实页放行

## 对抗思路

三条原则：

1. **不硬刚，分层降级**：从最便宜的 `curl_cffi` 试起，逐级升级到纯 CPU 执行
   VM（iv8/nodenv/sdenv），最后才动用真浏览器。约 60% 学校在第一层就通过。
2. **Cookie 一旦求出就按域缓存复用**：挑战求解 13-16s，但 Cookie 有效期内
   快路径只要 1-2s——把昂贵操作摊薄。
3. **失败语义统一**：每层失败返回空值交给上层，绝不把挑战页当成功页返回
   （假成功是这套体系最危险的失败模式——下游会误判"站点无数据"）。

```
smart_fetch(url) → (html, method)
  │
  │  ① curl_cffi ——— TLS 指纹模拟(chrome131)，无 WAF 站点一步直达 (~60% 学校)
  │  ② 系统 curl ——— libcurl 原生指纹。有的 WAF 按 TLS 指纹拦 curl_cffi
  │  │                却放行系统 curl（暨大实测：502 → 200）
  │  ③ iv8 ——————— Python 原生 V8 扩展，C++ 层浏览器环境，跑挑战 VM
  │  ④ nodenv ——— 手写 Node vm 补环境（零 npm 依赖）跑 VM
  │  ⑤ RsSpider —— sdenv(jsdom) 补环境 + 9333 常驻浏览器 Cookie 工厂
  │  ⑥ DrissionPage / CDP / CloakBrowser —— 真浏览器渲染兜底
  ▼
 (html, method)   —— 全部失败返回 ("", "blocked")
```

另有**方法偏好快路径**：同域上次成功的方法先试（TTL 内），重大类站点省去
iv8 每页 30s 的白耗（`util/cookies/_method_pref.json`）。

## 五级降级链

`util/smart_fetch.py` 的 `smart_fetch(url)` 是全仓库统一请求入口，
返回 `(html, method)`，`method` 标记命中层级（用于审计与偏好记录）：

| 层 | method 标记 | 原理 | 覆盖 | 成本 |
|---|---|---|---|---|
| ① curl_cffi | `curl_cffi` | `impersonate="chrome131"` 模拟 Chrome TLS 指纹 | 无 WAF 站点（~60%） | ~1s |
| ② 系统 curl | `system_curl` | subprocess 调系统 libcurl（不同 TLS 指纹） | 按 TLS 指纹拦 curl_cffi 的站 | ~1s |
| ③ iv8 | `iv8` | Python 原生 V8（C++ 实现浏览器 API）执行挑战 VM | classic + scu/njust 类形态 | 秒级 |
| ④ nodenv | `nodenv` | 手写 Node `vm` 沙箱 + 补环境（`util/rsenv/nodenv/`） | classic 412 形态 | 13-16s/轮 |
| ⑤ RsSpider | `ruishu` | sdenv(jsdom) 补环境 + 9333 常驻浏览器 | 全站点（含 scu 锁定模板等难形态） | 8-45s |
| ⑥ 浏览器渲染 | `drission`/`cdp`/`cloakbrowser` | DrissionPage 窗口池 / CDP 常驻 / 隐身 Chromium | 网络层瑞数 + JS 渲染壳 | 最重 |

层 ⑥ 受 `BROWSER_TIERS` 开关门控（**默认 off**，见[配置开关](#配置开关)）；
层 ⑤ 的 9333 常驻浏览器是 Cookie 工厂、内存可控（单实例 ~400MB），**不受该
开关影响**——它是强瑞数校（兰大）唯一兜底，门控即断粮（2026-09-11 定案）。

## 三条纯 CPU 求解器对比

三条求解链按优先级排列，前者失败自动降级后者。共同点：**全程直连**（瑞数
Cookie 与出口 IP 强相关，走代理换出口即失效——隧道代理不但无益还会把代理
出口的挑战态混入 Cookie 链）。

| | ③ iv8（`iv8_rs.py`） | ④ nodenv（`rs_cookie.py` + `rsenv/nodenv/`） | ⑤ sdenv（`handleRuishu.py` + `rsenv/generate_cookie.js`） |
|---|---|---|---|
| 引擎 | Python 原生 V8 扩展（C++ 层 BOM/DOM/Canvas） | Node `vm` 沙箱 + 手写补环境（零 npm 依赖） | sdenv 框架（jsdom 全量补环境，npm 依赖） |
| 请求 | 系统 curl（北邮等站对 curl_cffi 静默丢连接，系统 libcurl 0.3s 拿到挑战页） | curl_cffi（chrome110 + Win/138 UA） | curl_cffi（chrome131） |
| 执行 | 链式 eval：内联脚本 → VM 脚本 → 末段调用 → pump 事件循环 | `run_vm.js` 解析挑战页 → `env.js` 补环境 → eval VM → 轮询 `document.cookie` | jsdom 全流程执行，**阻止 `location.replace` 重定向**让 VM 跑完 |
| 形态覆盖 | classic + scu/njust 类（全形态通用） | classic 412（lzu/bupt/njnu，实测 15/15）；scu/njust 形态不支持 → 自动记账跳过 | 全站点 |
| Cookie 缓存 | `util/cookies/<host>.iv8.json`（TTL 7200s） | `util/cookies/<host>.nodenv.json`（TTL 3600s） | `util/cookies/<域key>.json`（TTL 3600s） |
| 并发控制 | 信号量 3（槽满立即拒绝不排队，防 15 线程堆死） | 形态不支持跳过账本（TTL 86400s，过期自动重试自愈） | 9333 单实例 flock 启动锁 + sdenv 超时负缓存 30min |
| 失败语义 | 空串交上层 | None 交上层；**404=Cookie 路径失配** → 清缓存重解 | None 交上层（浏览器路径） |

### 关键实测沉淀（写进代码注释的教训）

- **经典瑞数要打多轮**：`enable_` cookie → P cookie → 放行，最多 3 轮；
  每轮 VM 生成的 Cookie 必须**种回环境**再解下一轮（北邮实锤：不种回永远
  重复出 `enable_`）。重大类站点实测 3 轮才通，max_rounds=2 时 25/28 误判
  "形态不支持"。
- **响应 Set-Cookie 必须入罐**：浏览器自动存 O cookie，curl 不会——缺 O 则
  VM 永远算不出 P（北邮实锤）。
- **成功判定只看状态码**：真实 200 页面自带 `$_ts.nsd` 刷新脚本，按内容
  特征判挑战会误杀真页面 → VM 重跑死循环（bupt 实锤）。
- **UA 一致性是这个体系最脆弱的环节**：服务端校验 Cookie 内编码的指纹与
  请求的一致性，UA 不匹配直接 400。三条链各自闭环：
  iv8 链全程 Mac/Chrome131（curl `-A` 与 VM navigator 一致）；nodenv 链
  HTTP 头 Win/Chrome138 + VM navigator Mac/Chrome131（2026-08-31 对齐 sdenv
  实测定案，见 `env.js` 注释——`rs_cookie.py` 头部的旧注释表述已过时）；
  sdenv 链由框架统一。**改 UA 必须同链全改，且必须实测验证**。
- **失效 Cookie 污染挑战态**：带失效缓存 Cookie 请求拿到的 412 页，VM 解出
  的 P-cookie 与服务器基准对不上，3 轮全 412（重大实锤）。链内检测到缓存
  Cookie + 412 → 清缓存裸请求重取纯挑战态，不消耗轮次。
- **深度页 Cookie 路径失配**：深度页解出的 Cookie 用于首页 → 服务端 404
  （重大艺术学院实锤）。404 + 有缓存 Cookie → 清缓存重新走 412 挑战。

## 浏览器层

纯 CPU 链覆盖不了的（网络层瑞数、JS 渲染壳、锁定模板形态）交给真浏览器：

| 组件 | 端口/形态 | 用途 | 生命周期 |
|---|---|---|---|
| 9333 常驻 Chromium | `remote-debugging-port=9333` | RsSpider 的 Cookie 工厂（sdenv 失败 → DrissionPage 真 Chrome 指纹 → Playwright 兜底三级生成） | flock 启动锁 + 锁内复用 + 闲置交 watchdog 回收；进程退出**不杀** |
| DrissionPage 窗口池 | 9340 起，3 窗口 × 4 标签 | 页面渲染（`drission_pool.py`） | 空闲回收 `BROWSER_IDLE_REAP=1800s` |
| CDP 常驻浏览器 | 9222 | Playwright 复用通道 + `stealth.min.js` 注入（`cdp_util.py` / `browser_lifecycle.py`） | 同上，flock 启动锁 `/tmp/chrome9222.launch.lock` |
| CloakBrowser | 隐身 Chromium | 最后手段（免费版 1 并发串行） | 按需 |

**进程安全三防**（历史事故沉淀，详见 `browser_lifecycle.py` 与代码注释）：

1. **防互搏**：跨进程单例浏览器的启动段必须持 flock 文件锁，锁内先读
   `/json/version` 见活实例直接复用，严禁无条件 pkill（多 worker 并发
   「检查→杀→拉起」曾造成 8-18 次/分钟的启动-被杀循环）。
2. **防自启泄漏**：端口在监听 ≠ 常驻活着。连接前 socket 验证 + `/json/version`
   ws 身份核对 + **监听进程二进制校验**（9333 被 DrissionPage 自启的系统
   Chrome 占用时杀之重拉——同 bundle ID 单例会劫持个人 Chrome）。
3. **防劫持**：项目浏览器一律独立 Chromium（`PROJECT_CHROME_BIN`），与
   个人 Chrome 不同 bundle ID，互不干扰。

## Cookie 生命周期管理

```
请求 → 缓存快路径(TTL 内, 1-2s)
        │ 412/202（权威失效信号）
        ▼
      清缓存 → 裸请求取纯挑战页 → VM 重解 → 新 Cookie 落盘
        │
        ├─ 404 + 有缓存 → Cookie 路径失配 → 清缓存重走挑战
        ├─ VM 跑满无产出 → 形态不支持账本(TTL 86400s, 直跳下层)
        ├─ sdenv 生成超时 → 负缓存 30min(直跳其他方法)
        └─ 成功 → 持久化(原子写 tmp+rename) + 记录方法偏好
```

所有 Cookie 存 `util/cookies/`（已 gitignore）：
`<host>.iv8.json` / `<host>.nodenv.json` / `<域key>.json` /
`_method_pref.json`（方法偏好）/ `_nodenv_skip.json`（跳过账本）。

## 并发与进程安全

| 机制 | 位置 | 语义 |
|---|---|---|
| iv8 求解信号量(3) | `iv8_rs.py` | 槽满**立即拒绝不排队**——15 线程堆在信号量上会把 spider 预算全烧在等待（电子科大实锤：单跑 10.6s 解出，批内 150-255s 失败） |
| flock 启动锁 | `handleRuishu.py` / `browser_lifecycle.py` | 跨进程单例浏览器启动段互斥；锁内复用活实例 |
| Cookie 原子写 | 各求解器 | `tmp` 写入 + `rename`，线程锁保护 |
| 浏览器活动时间戳 | `browser_ops.log` | watchdog 据此空闲回收；「8+ 次/分 launch」= 互搏信号 |

## 工程铁律

1. **瑞数路径全程直连**（`proxies=None`）：Cookie 与出口 IP 强相关，隧道
   代理换出口即失效。本地 IP 实测更稳（兰大/南师大：代理 412 / 直连 200）。
2. **成功判定只看状态码 + 长度 + 非挑战页**，不做内容特征判挑战（防误杀
   真页面导致 VM 死循环）。
3. **每层失败必须交上层**，绝不把挑战壳页当成功返回（假成功 = 下游误判
   "站点无数据"）。
4. **改 UA 必须全链一致 + 实测**；改补环境必须重放验证。
5. **单例浏览器只许锁内启动/复用，严禁无条件 pkill**。

## 配置开关

`.env`（模板见 `.env.example`）：

| 变量 | 默认 | 说明 |
|---|---|---|
| `BROWSER_TIERS` | **`off`** | 页面渲染层总开关。`off`=纯 CPU 链（curl_cffi/系统curl/iv8/nodenv/sdenv）；`on`=启用 DrissionPage/CDP/CloakBrowser 渲染层。⚠️ **留空≠默认**：显式空值会被解析为"开"，小内存机器请显式写 `off`。9333 Cookie 工厂不受此开关影响 |
| `RS_DISABLE` | 空=启用 | `1`/`on`/`true` 时临时关闭 RsSpider(sdenv) 层（如 9333 启动即死时止损），瑞数站降级 blocked 收敛重试 |
| `RS_COOKIE_TTL` | `3600` | nodenv Cookie 缓存秒数 |
| `IV8_COOKIE_TTL` | `7200` | iv8 Cookie 缓存秒数 |
| `IV8_UA` | 内置 Mac/131 | 覆盖 iv8 链 UA（与 VM 环境一致，慎改） |
| `NODENV_SKIP_TTL` | `86400` | nodenv 形态不支持跳过账本 TTL（过期自动重试自愈） |
| `BROWSER_IDLE_REAP` | `1800` | 浏览器空闲回收秒数 |
| `PROJECT_CHROME_BIN` | 自动探测 | 项目浏览器二进制（独立 Chromium，防劫持个人 Chrome） |
| `DRISSION_MAX_WINDOWS` / `DRISSION_MAX_TABS_PER_WINDOW` / `DRISSION_PORT_BASE` | 3 / 4 / 9340 | DrissionPage 窗口池规模 |
| `CDP_BASE_URL` | `http://127.0.0.1:9222` | CDP 常驻浏览器地址 |

| 组件 | 安装 | 必需性 |
|---|---|---|
| curl_cffi | `uv sync`（pyproject） | ✅ 必需 |

| sdenv（jsdom 补环境） | `npm ci --prefix util/rsenv` | ⑤ 层需要；不装则 ⑤ 自动跳过（抛错 → 上层降级） |

不装任何可选依赖时：链退化为 curl_cffi → 系统 curl → nodenv，依然能覆盖
大部分无 WAF 与 classic 瑞数站点。

## 排查手册

| 症状 | 诊断 | 处置 |
|---|---|---|
| 某站永远 `blocked` | `fetch_method_label` 看命中的最后一层；手动逐层试 | 网络层瑞数（TCP reset）→ 换网络出口；IP 黑名单 → 等待/换 IP |
| 反复 412 死循环 | 检查是否带失效缓存 Cookie 请求（见上文"污染挑战态"） | 代码已自动清缓存；手动处置删 `util/cookies/<host>.*.json` |
| VM 解出 Cookie 仍 400 | UA 链不一致 | 对照三条链 UA 矩阵，全链统一后实测 |
| nodenv 每次白跑 13-16s | scu/njust 类形态不支持 | 已自动记账跳过；确认 `_nodenv_skip.json` 存在且未过期 |
| iv8 批内大面积超时 | 信号量槽满 + CPU 竞争 | 正常设计（拒绝不排队）；降低 worker 并发 |
| 9333 启动即死/循环重启 | 互搏或二进制劫持 | 看 `browser_ops.log` 频率；临时 `RS_DISABLE=1` 止损；确认 `PROJECT_CHROME_BIN` 是独立 Chromium |
| sdenv 层每页白等 65s | 生成超时无负缓存命中 | 2026-10-25 已加 30min 负缓存；确认代码版本 |
| 挑战壳被当成功页返回 | `_is_challenge_page` 未命中新形态 | 把壳页特征（如 `setTimeout("xx(N)")`）补进 `_WAF_CHALLENGE` 模式表 |
