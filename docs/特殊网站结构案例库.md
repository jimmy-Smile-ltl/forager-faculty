# 特殊网站结构案例库 — 反常规形态的院系站点档案

> **English summary**: A catalog of the most unusual faculty-site structures
> encountered while crawling 5,287+ department websites across Chinese
> universities. Grouped into six families: (1) rosters that live *outside* HTML
> — embedded PDFs, title-rank columns, school-level JS platforms; (2) entries
> that are not "homepages" — language-selector pages, school-wide directories;
> (3) fake or rewritten links — JS-rewritten hrefs, iframe-nested tsites
> platforms, JS-array data; (4) whole-site encryption shells — AES-GCM and
> eval-jump obfuscation; (5) counterintuitive URL shapes — per-teacher
> `list.htm` detail pages, CMS path migrations; (6) unusual indexing — A–Z
> letter indexes that override pagination. Each entry lists the URL, the
> structural quirk, and the countermeasure that finally worked. The closing
> section distills the anti-misjudgment discipline these cases taught: when a
> page has real navigation but no roster, suspect PDF/subpage/JS/platform —
> never conclude "no faculty" prematurely.

> **数据边界**：本文档仅收录**公开网站的结构特征**（URL、页面形态、反爬类型），
> 不含任何教师姓名、邮箱、内网地址或采集凭证。

## 背景

全库 5,287+ 个院系站点中，绝大多数是「导航 → 师资队伍页 → 教师列表 → 详情页」的
标准 CMS 结构。少数站点结构反常规，曾被误判为「站点不可达 / 无师资 / JS 壳」三类
假终态。本文档按形态家族收录典型案例，供爬虫开发者与后续采集工作参考。

## 一、名单根本不在 HTML 里

### 1. 重庆大学-辛辛那提联合学院 — 师资名单是一个 43 页大 PDF

- **URL**: `http://uc.cqu.edu.cn/xygk/zfsz.htm`（中方师资页，瑞数 412 保护）；
  PDF 本体 `http://uc.cqu.edu.cn/__local/.../*.pdf`（**直连可下**，无需瑞数 cookie）
- **主要特点**: 页面正文只有一句「如果您无法在线浏览此 PDF 文件，则可以下载
  免费小巧的福昕(Foxit) PDF 阅读器」——真正的师资名单在 iframe 指向的
  **43 页 PDF**（2.8MB）里，**每人一页**：姓名 / 职称 / 邮箱 / 主讲课程 /
  个人简介 / 研究方向。HTML 零名单，渲染兜底拿到 66KB 完整渲染页仍提取 0 人
  （`_is_js_shell` 判「有师资词无姓名行」是**正确判定**，不是误杀——名单真的
  不在 HTML 里）。「美方师资」页（`xygk/mfsz.htm`）是纯空壳，无任何名单。
- **提取细节**: 43 页 = 43 名教师，每页首行为姓名（2-4 中文字）。职称行有
  **三种变体**需覆盖：①独立职称行（`博士/教授/博导`）；②姓名+职称同行
  （`董庆兵 博士 研究员 博导`）；③无职称行（直接是邮箱）。职称词含「工程师 /
  高级研究员」等非常规档位。
- **对策**: 专项 PDF 解析（`script/collect_uc_pdf.py`）：瑞数破解链（iv8/nodenv）
  拿 HTML 页 → 提取 iframe PDF 地址 → PDF 直连下载 → pdfplumber 逐页提取 →
  按标准 teachers.csv 落盘 43 人 + `.fix_done`。

### 2. 北京化工大学 — 名单藏在「职称档」栏目

- **URL**: `https://mech.buct.edu.cn`（机械）、`https://sem.buct.edu.cn`（经管）等院系站
- **主要特点**: 教师名单不在常规「师资队伍 / 教师名录」栏目，而在 **「职称档」**
  栏目页（如 164 人的完整名单页）。发现链的词表里没有「职称档」这个词，导致整个
  学院被判「无师资页」。
- **对策**: 发现链栏目词表补入职称类词汇（职称档 / 职称名册等）。

### 3. 重庆大学电气工程学院 — 校级 JS 平台，链接不是锚

- **URL**: `http://www.cee.cqu.edu.cn/`（院官网）+ 校级平台 `faculty.cqu.edu.cn`
  （`jsxc.jsp`，375KB 纯 JS 渲染）
- **主要特点**: 名单实际在校级教师平台，**教师链接不是 `<a>` 锚**（22 个可点击
  链接 0 个能捕获 URL），平台按拼音字母分页。院系官网的名单反而不全。
- **对策**: 平台两 DOM 形态 + PAGENUM 分页适配；最终以院系官网 17 页分页全采
  （165 人）。

## 二、入口不是「首页」

### 4. 重庆大学土木工程学院 — 首页是语言选择页

- **URL**: `http://civil.cqu.edu.cn/`
- **主要特点**: 首页本身是**语言选择页**（中文 → `xzwb/sy.htm`、English →
  `ecivil`），入口全是**图片链接、无锚文本**。常规发现链读不到任何可跟随的
  文字链接，永远进不了真正的学院主页。
- **对策**: 「入口选择页跟随」机制：页面锚数 ≤6 且无师资词 → 跟随第一个本站
  内部入口递归一层。土木学院从 61 人修复到 263 人。

### 5. 中央美术学院 / 中国美术学院 — 全校一个大名录

- **URL**: `www.cafa.edu.cn` / `www.caa.edu.cn`（学校级名录站）
- **主要特点**: 没有院系级站点，全校教师集中在**一个大型名录页**，需按院系
  切分。常规「按院系 URL 采集」完全落空。
- **对策**: 名录切分采集专项（`cafa_collect.py` / `caa_collect.py`）。

### 6. 中央音乐学院 / 上海音乐学院 / 中央戏剧学院 — 官网与院系不对应

- **主要特点**: 官网结构无法与院系清单一一对应，直接按院系抓会错位。
- **对策**: 显式映射专项（`art_college_fix.py`）。

## 三、链接是假的（JS 改写 / 嵌套 / 数组数据）

### 7. 北京大学经济学院 — href 是 JS 改写型相对链接

- **URL**: `econ.pku.edu.cn` 教师目录页
- **主要特点**: 页面静态 href 是 **JS 改写型相对链接**，直接拼接成 URL 访问必
  404——必须真实渲染执行 JS 才能拿到有效链接。曾导致整院「无师资页」误判。
- **对策**: 9222 渲染取真实 href + 姓名→URL 映射机制。

### 8. tsites 平台族 — iframe 嵌套 + 平台分页

- **URL**: `http://fe.bnu.edu.cn/`（北师教育学部）、`https://homepage.hit.edu.cn`
  （哈工大）、`https://smc.sjtu.edu.cn`（上交）等
- **主要特点**: 师资数据在 **iframe 嵌套**的深层（两层 DOM 形态），分页参数
  `PAGENUM`，URL 特征 `urltype=tsites.CollegeTeacherList`。初版 879 条全错，
  修复后 109 条。
- **对策**: iframe 递归 + 平台 URL 硬拒守卫 + 双层分页适配。

### 9. 浙江大学（部分院系）— 教师数据在 JS 数组里

- **URL**: `zju.edu.cn` 院系站（`list._college` JS 数据形态）
- **主要特点**: 教师名单不存在于 DOM，而在页内 **JS 数组**（`list._college`）中，
  需要解析 JS 数据而非解析 HTML。
- **对策**: JS 数据解析路径 + 模块选择器修复。

## 四、全站加密壳（拿到 HTML 也没用）

### 10. 中南财经政法大学 — 全站 AES-GCM 加密壳

- **URL**: `zhxmt.zuel.edu.cn`（91KB 挑战页形态）
- **主要特点**: 全站部署 **AES-GCM 加密壳**（content_container + 混淆 JS），
  无瑞数特征码、无 challengeId——旧检测表漏判，被当成功页返回，下游提取 0 人。
- **对策**: 纯 CPU AES-GCM 破解（`loader_challenge.crack_aes_gcm_shell`），
  一次 GET 零浏览器零挑战往返。

### 11. 中山大学附属医院 — jp()/bq() eval 跳转壳

- **主要特点**: 2214B 壳页面：oo 数组 + 轮解密 + XOR + `eval("qo=eval;qo(po);")`
  跳转。无瑞数 / challengeId 特征，被当成功返回。
- **对策**: 壳特征词进 `_WAF_CHALLENGE` 检测表；科室页跟进渲染提取。

## 五、反直觉的 URL 形态

### 12. 长安大学等 — 每人一个 `list.htm` 详情页

- **URL**: `js.chd.edu.cn/gcjxxy/czy/list.htm`（长安公路学院形态）
- **主要特点**: 每个教师一个 `/拼音缩写/list.htm` 详情页——**URL 名叫 list.htm，
  实际是个人主页**。全库 6,291 条该形态，仅 55 条（0.9%）是真列表页；旧规则
  按「list.htm = 列表页」全部误杀。
- **对策**: `is_list_htm_person` 豁免判定——前段是栏目词（szdw/gzry/...）才是
  列表页，否则（拼音缩写 / 数字 ID）是详情页。

### 13. 北京大学法学院 — 改版加目录层，ID 不变

- **URL**: `www.law.pku.edu.cn/szdw/zzjs/...`
- **主要特点**: 改版在 `szdw/zzjs/` 下新增一层 `azyxjs` 子栏目，**详情 ID 不变**：
  旧路径全 404，换路径即活。
- **对策**: URL 修复规则（`util/url_rewrites.py`）。

### 14. 中国地质大学（北京）— CMS 统一加 `/scholar` 目录

- **URL**: `scholar.cugb.edu.cn`（旧 `.../scholarDetail/2499.shtml` 全 404）
- **主要特点**: CMS 升级后所有详情页路径统一加一层 `/scholar` 前缀，旧路径
  全站失效。
- **对策**: 同族 URL 改写规则。

## 六、索引结构诡异性

### 15. 云南大学经济学院 — A-Z 字母索引页

- **URL**: `http://www.eco.ynu.edu.cn/`（师资页 `jsjs.htm`）
- **主要特点**: 师资页是 **A-Z 字母索引页**（一串单字母链接，名单在子页），
  曾因「无名单行」被误判成 JS 壳而放弃。
- **对策**: 字母索引豁免（≥5 个单字母链接即视为索引页）+ 子页跟进提取。

### 16. 北京大学计算机学院 — 字母索引覆盖数字分页

- **URL**: `cs.pku.edu.cn` 师资列表页
- **主要特点**: 数字分页之外还有**字母索引分页**，只抓数字分页漏掉一半教师
  （26 → 133 人）。
- **对策**: 字母索引覆盖数字分页 + BFS 分页闭包。

## 判别纪律（这些案例共同教会的）

1. **页面有真实导航但无名单** → 先怀疑名单在 PDF / 职称档子栏目 / JS 数组 /
   校级平台 / iframe 深层，而不是下结论「没有教师」。**特别地**：正文出现
   「无法在线浏览此 PDF / 下载 PDF 阅读器」提示或 `<iframe ... .pdf>` → 名单
   载体几乎必然是 PDF，直接下载解析（PDF 文件本体通常不受瑞数保护，直连即可）。
2. **404 不等于站点死** → 先查域名变体（www / 裸域）、改版路径（加目录层 /
   换域名），再判死。
3. **412 / 挑战页不等于不可解** → 只是默认挑战响应；是否有名单取决于破解路径，
   与「站点是否活着」无关。
4. **URL 名字会骗人** → `list.htm` 可能是个人详情页；「师资队伍」栏目可能
   是空壳，名单在别的栏目。
5. **每个终态都要留重审余地** — 结构升级（瑞数破解 / 渲染 / 规则）后，
   历史「无师资」终态必须重扫一遍，不能信任旧结论。
